# 저장소 전체 리팩터링 계획·진행 템플릿

아래 형식을 참고하되 저장소를 직접 조사한다. 확인하지 않은 수치나 상태를 만들어 쓰지 않는다.

## MASTER_PLAN.md

### 목표와 불변 조건

- 범위: 명시적 제외 항목을 포함한 저장소 전체 소스 인벤토리
- 보존 계약: 공개 API, IPC, 저장 형식, 오류·재시도 의미, 부수 효과 순서
- 기준선: 날짜, 브랜치, Git 변경 파일, 기존 실패
- 필수 검증: 패키지·도구 설정에서 확인한 명령

### 탐색 범위 인벤토리

| 영역 ID | 실제 경로 | 적격 파일 수 | 조사 담당 | 검토 상태 | 제외·보류 사유 |
| --- | --- | ---: | --- | --- | --- |
| R-001 | [실제 경로] | [개수] | 담당자 | pending | |

커버리지 확인: 모든 적격 추적 파일을 정확히 하나의 영역에 배정한다. 검토 영역 수와 의미 검토한 적격 파일 수를 각각 보고하며, 수정 파일 수로 대체하지 않는다.

### 의존성과 배치

| 배치 | 작업 ID | 선행 공유 계약 | 충돌 없이 수정 가능한 담당자 | 검증 게이트 |
| --- | --- | --- | --- | --- |
| 1 | T-001 ... | 없음 | 서로 다른 파일 | 집중 테스트 |

### 완료 조건

- 모든 조사 영역을 검토하거나 명시적 사유와 함께 차단 상태로 기록
- 채택한 모든 리팩터링 작업을 검증하거나, 사유와 함께 보류·차단
- 필수 최종 검증 실행 또는 실행 불가 사유 기록
- 남은 위험, 미조사 경로, 범위 밖 동작 변경을 명시

## TASKS.md

| 작업 ID | 영역 | 변경 목표 | 전용 수정 경로 | 선행 작업 | 위험도 | 검증 | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T-001 | R-001 | 혼합된 책임 분리 | apps/.../file.ts | 없음 | 중간 | npm ... | queued |

작업 상태는 `queued`, `in-progress`, `validated`, `needs-rework`, `deferred`, `blocked`를 사용한다. 영역 검토 상태는 `pending`, `reviewed/changes-needed`, `reviewed/no-change`, `blocked`를 사용한다. 병렬 작업 중 계획과 작업 큐는 통합 담당자만 갱신한다.

### 작업 전달 내용

- 작업 ID / 담당 경로 / 수정 금지 경로
- 기존 검증 기준선 결과
- 수정 경로와 정확한 변경 의도
- 보존한 계약 / 관찰된 동작 변경
- 실제 검증 명령과 결과
- 통합 우려 사항과 다음 단계
