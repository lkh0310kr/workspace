# PKMS Google Drive (`@pkms/google-drive`)

PKMS 플랫폼 adapter에서 함께 사용하는 Google Drive API와 workspace repository다.

- `GoogleDriveClient`는 Drive v3 요청, 인증 token 주입, 횟수가 제한된 rate-limit 재시도, immutable operation 업로드 복구, change-feed 페이지 조회를 담당한다.
- `GoogleDriveClient.searchFullTextPage`는 Drive의 색인된 `fullText` query를 제한된 page로 제공한다. `GoogleDriveWorkspaceRepository.searchFullTextPage`는 결과를 선택한 root 아래의 Markdown 파일로 한정한다. Drive 검색은 임의의 부분 문자열이 아니라 전체 단어와 따옴표로 묶은 구문을 찾는다. 따라서 이 API 기능은 editor의 정확한 로컬 콘텐츠 검색 계약을 대체하지 않는다.
- `GoogleDriveWorkspaceRepository`는 명시적으로 선택한 Drive 폴더를 재귀 PKMS tree에 대응시키고 파일·폴더 생성, 이동, 이름 변경, 휴지통 이동을 제공한다. `listDirectoryById`와 `getEntry`는 안정적인 item ID를 해석하고 요청한 tree branch만 가져오며, 관련 없는 directory를 열거하지 않는다. 폴더 이동은 source/target ancestry와 destination path만 확인하고 workspace 전체를 재귀적으로 조회하지 않는다. `createFolderOnce`와 `createFileOnce`는 workspace 범위 operation marker로 응답 유실 뒤 성공한 Drive 생성 작업을 복구하고 payload 충돌을 거부한다. `resolveGoogleDriveWorkspaceRoot`는 app 소유 `appProperties` marker로 기기 간 root를 찾고, 없을 때만 새 root를 만든다. root가 여러 개여서 모호하면 중단한다.
- `IndexedDbDriveOutbox`는 안정된 순서의 operation과 content bytes를 로컬에 보관한다. 호출자가 Drive의 durable acknowledgement를 확인할 때까지 operation은 pending 상태다.
- `IndexedDbGoogleDriveReplica`는 root별 metadata, 필요할 때 내려받은 bytes, Drive changes cursor를 보관한다. cursor를 앞으로 옮기기 전에 change page를 적용하며, 원격 폴더가 삭제돼도 pending edit이 있는 cached descendant는 보존한다.
- `GoogleDriveOperationLog`는 숨겨진 `.pkms-sync/operations` 폴더에 변경할 수 없는 checksum 포함 operation record를 기록한다. Drive `appProperties`는 각 operation의 workspace, type, 영향받는 item을 색인한다. Sync는 replica의 durable cursor 이후 Drive changes feed에 나타난 operation 파일 내용만 읽는다. 최초 연결에서는 모든 이력을 다시 적용하지 않고 baseline을 설정한다. Markdown 파일을 열 때 해당 파일의 seed와 Yjs update만 조회·다운로드한다.
- `GoogleDriveYjsDocumentStore`는 Markdown 문서 하나를 필요할 때 연다. pending create, 결정적인 seed operation 또는 해당 Drive 파일에서 내용을 가져와 seed를 만들고 로컬 Yjs update를 queue한다. 모든 파일 내용을 한꺼번에 다운로드하거나 색인하지 않는다. 제품 검색 index와 플랫폼 adapter는 별도로 연결해야 한다.
- `GoogleDriveOperationApplier`는 tree operation을 replay하고 Yjs/document 및 asset projection 작업을 위임한다. `GoogleDriveAssetConflictMaterializer`는 asset 하나의 immutable replacement 이력을 결정적인 operation 순서로 해결하고, 서로 다른 이전 bytes를 안정적으로 표시되는 conflict file로 남기며 모든 replica에서 같은 승자를 projection한다. operation에 인과 관계가 있는 base hash가 아직 없으므로 이 보수적인 규칙은 순차적인 과거 버전도 conflict file로 드러낼 수 있다. 완전한 binary 편집과 base 인식 conflict UX는 아직 구현되지 않았다.
- `GoogleDriveSyncEngine`은 durable outbox 항목을 log에 추가하고 root별 durable cursor 다음의 변경분을 읽는다. 주입된 idempotent reconciliation callback으로 operation을 replay하고 reconciliation과 cursor 저장이 모두 성공한 뒤에만 로컬 작업을 확인 처리한다. 실제 reconciliation/projection 구현은 제품 adapter가 제공해야 한다.
- `createGoogleDriveWorkspaceSync`는 repository, operation log, durable outbox, Yjs document store를 하나의 replay pipeline으로 조립한다. Web과 Desktop은 공용 asset conflict materializer를 연결하며, durable store와 인증은 플랫폼 adapter가 공급한다.
- `GoogleDriveWebOAuth`는 사용자 동작 중에만 Web 인증을 수행하고 access token을 memory에 보관한다. token이 만료되면 재인증을 요청하며 browser storage에는 token을 저장하지 않는다.
- Web과 Desktop은 Drive access를 허용하기 전에 Google 계정 email을 확인한다. `VITE_GOOGLE_DRIVE_ALLOWED_EMAILS`(Web build)와 `GOOGLE_DRIVE_ALLOWED_EMAILS`(Desktop build)는 쉼표로 구분한 대소문자 무시 allowlist다. 값이 없거나 비어 있으면 기본 거부한다. 현재 local production build는 `lkh0310kr@gmail.com`을 사용한다. 이 값은 client-side 정책 gate이지 secret이나 server-enforced authorization이 아니다. Google `drive.file` 권한은 각 계정이 app에서 만들었거나 명시적으로 연 파일로 계속 제한한다.
- Desktop OAuth는 Google token endpoint가 Desktop client 값을 포함하지 않은 PKCE code 교환을 거부했기 때문에 build 시 `GOOGLE_DRIVE_DESKTOP_CLIENT_SECRET`도 읽는다. Desktop client 값은 기밀로 유지할 수 없고 app에 포함되므로 server secret으로 취급하면 안 된다. 로컬 값은 Git에서 제외된 `.env.production.local` 파일에 둔다.
- 이제 `/` Web route는 기본적으로 Google Drive를 사용하며 공용 Markdown editor와 직접 연결 repository를 이용해 branch 목록, Markdown 열기/편집/저장, 기본 tree 변경, workspace Markdown을 대상으로 한 `Cmd/Ctrl+Shift+F` Drive 색인 단어/구문 검색을 제공한다. 이전 API 기반 PKMS UI는 마이그레이션 fallback으로 `/existing-pkms`에 남아 있다. 검색은 임의의 부분 문자열, 일치한 줄 preview, 전체 workspace의 offline 검색을 아직 제공하지 않는다. Sync pipeline은 binary replacement operation을 보존하고 projection하지만 Web route에는 binary 편집 기능이 없다. 마이그레이션 완료와 PKMS의 나머지 기능은 아직 연결되지 않았다.
- Desktop에는 root 검색·생성, branch 목록, Markdown 열기/저장, 기본 tree 변경, sync를 위한 main-process workspace service와 제한된 preload IPC가 있다. Native SQLite adapter는 operation outbox와 Yjs snapshot을 WAL 및 full synchronous commit으로 저장한다. PKMS pane은 직접 Drive 모드를 기본으로 사용하며 기존 PKMS source를 명시적인 마이그레이션 fallback으로 남긴다. 계정 단위 Desktop runtime 확인 전 native OAuth client ID를 등록하고 설정해야 한다.
- 현재 구현 범위에서 OAuth 동의, token persistence, durable local outbox, Yjs operation orchestration, 플랫폼 UI는 Web과 Desktop adapter의 책임이다. iOS는 이후 단계에서 같은 provider contract를 구현할 수 있다. 이 package는 PKMS server나 Worker를 사용하지 않는다.

대상 storage와 synchronization 계약은 [Google Drive 직접 sync](../../docs/architecture/pkms/google-drive-direct-sync.md)에 문서화되어 있다. 이 package는 공용 기반이며, 존재만으로 제품 client가 현재 PKMS API에서 전환되는 것은 아니다.
